# 管理员操作手册

> 适用对象：负责资源采集、系统配置与审计的管理员。后台入口为 `/admin`，需要账号密码登录。

## 1. 登录与初始账号

- 首次启动时，若环境变量 `ADMIN_PASSWORD` 未设置，系统会生成随机密码：
  - 启动日志中打印一次；
  - 同时写入 `data/initial-admin-password`（权限 600）。
- 登录后请立即到「系统设置 → 修改密码」更换，并删除初始密码文件。
- 会话有效期默认 12 小时；修改密码会使其他会话失效。
- 忘记密码时可在服务器执行密码重置脚本（见常见问题）。

## 2. 概览

概览页展示：

- 已缓存的 VS Code 版本数、插件数、Remote-SSH 版本数；
- 存储占用、磁盘剩余空间；
- 今日 PV / UV / 下载量；
- 最近任务、审计事件与下载记录。

失败任务会在任务卡片中显示数量，点击进入「任务中心」处理。

## 3. 缓存 VS Code 安装包

进入「VS Code 缓存」：

1. 在版本列表中搜索并选择目标版本（支持多选）。
2. 平台默认勾选 10 个主流平台：
   Windows x64/ARM64 用户安装、macOS Intel/Apple Silicon、Linux x64/ARM64 的 tar.gz/deb/rpm。
3. 其他平台（系统安装、便携 zip、ARMHF、macOS 通用包）在「更多平台」中选择。
4. 可先对某个版本点击「探测平台」，系统会逐个检查官方是否存在该平台的包，避免创建注定失败的任务。
5. 点击「缓存所选」，系统按「版本 × 平台」拆分为独立任务。
6. 版本列表的 commit 列会显示已缓存安装包的 commit；尚未显示时可点击该行的「解析 commit」，或点击工具栏「自动解析本页 commit」批量解析当前页。

注意事项：

- 不是所有历史版本都提供全部平台（例如旧版本的 ARM64 包可能不存在）。探测结果会显示 404。
- 单个版本全平台约占用 1–2 GB，请先确认磁盘余量。
- 已缓存的版本/平台会显示徽标，默认跳过；勾选「强制重新缓存」可重新下载。
- 版本列表需要访问外网；离线时页面会展示已缓存版本并给出提示。

## 4. 插件管理

### 4.1 上传 .vsix

进入「插件管理 → 上传」：

1. 拖入或选择 `.vsix` 文件（默认上限 200 MB，可在设置中调整）。
2. 系统自动解析：
   - 插件 ID（`publisher.name`）、显示名、版本、Publisher；
   - 支持的 VS Code 引擎范围；
   - 依赖插件、Extension Pack、分类、关键词、许可证、仓库地址；
   - 图标（PNG/JPEG/GIF/WebP）。
3. 解析成功后立即入库，前台可见。
4. 同一插件同一版本重复上传会返回冲突。如需替换，请先在存储管理中删除旧记录。

安全检查：

- 校验 zip 魔数、必需条目、条目数量与解压上限，不解压整包，防 zip 炸弹与路径穿越。
- 可配置 `CLAMSCAN_PATH` 接入 ClamAV 做病毒扫描（可选）。
- 上传文件先落到临时目录，校验通过后原子移动。

### 4.2 管理已缓存插件

- 支持按名称/Publisher 搜索与分页。
- 可下载、删除、查看 SHA256 与平台。
- 删除会同时移除 vsix、图标与分类关联，并写入审计日志。

## 5. 市场浏览与一键缓存

进入「市场浏览」：

1. 选择数据源：**官方 Marketplace**（默认）或 **Open VSX**。
2. 按关键词、分类、排序（相关性/下载量/更新时间）检索。
3. 点击「缓存」后，系统展示该插件的全部历史版本（最多 120 个）与目标平台：
   - 优先选择通用包（universal）；
   - 若插件只提供平台专用包，默认选 `linux-x64`，请按实际使用环境选择。
4. 确认后创建缓存任务，成功即在前台可见。

合规提示：

- 官方 Marketplace 的 gallery 接口主要面向 VS Code 客户端，第三方客户端使用可能存在 ToS 限制，请自行评估。
- Open VSX 完全开放，适合对合规要求严格的场景；但部分微软官方闭源插件不在其中。
- 本项目不附带任何微软二进制或插件包，缓存内容由管理员在部署环境中自行采集。

## 6. Remote-SSH Server 缓存

进入「Remote-SSH 缓存」，支持两种采集方式。

### 6.1 自动缓存（从镜像源下载）

1. 在「系统设置 → 数据源 → Remote-SSH Server 镜像源地址」填写镜像源。默认是
   `https://update.code.visualstudio.com`，镜像需保持相同路径结构：
   `<镜像源>/commit:<commit>/server-<platform>/stable`。
2. 在内网镜像场景，把镜像主机加入 `NETWORK_ALLOWED_PRIVATE_HOSTS`，否则 SSRF 防护会拒绝私网地址。
3. 返回「Remote-SSH 缓存」，选择与客户端一致的 VS Code 版本（可多选）。
4. 默认平台为 `linux-x64`、`linux-arm64`、`linux-armhf`；Windows/macOS 远端在「更多平台」中选择。
5. 系统自动解析该版本的 commit，并生成下载地址；任务成功后前台显示版本、commit、平台与 SHA256。

### 6.2 手动上传（离线包导入）

适用于管理端无法出网、或镜像源不可用的情况：

1. 在可联网机器下载标准 server 包，例如
   `vscode-server-linux-x64.tar.gz` 或 `vscode-server-win32-x64.zip`。
2. 在「Remote-SSH 缓存」点击「手动上传 server 包」，拖入文件。
3. 系统读取包内 `product.json` 自动识别版本与 commit，并按
   `vscode-server-<platform>.tar.gz/.zip` 文件名识别平台；识别不到时可手动填写。
4. 点击「上传并入库」，成功后前台立即可见。

> 上传上限默认 1 GB，可在「系统设置 → 基本设置 → Server 包上传上限」调整。

### 6.3 commit 显示

版本列表的 commit 列优先显示已缓存 server 的 commit；server 尚未缓存时，会回退到已缓存 VS Code 安装包的 commit。
仍未显示时可点击该行的「解析 commit」，或点击工具栏「自动解析本页 commit」批量解析当前页；commit 会完整显示并提供复制按钮。

注意：server 平台取决于**远端主机**，不是客户端。升级客户端后需重新缓存或导入对应版本的 server。

## 7. 任务中心

任务状态：`排队中`、`下载中`、`成功`、`失败`、`已取消`。

- 进度条显示已下载/总字节；失败原因保存在任务详情。
- 可对失败或已取消任务重试；重试会保留 `.part` 分片并尽量断点续传。
- 失败会自动按 1s/2s/4s… 退避重试（默认最多 3 次，可配置），仍失败则等待管理员处理。
- 服务重启时，运行中的任务会自动重新排队。
- 「重试全部失败」适合批量恢复网络中断后的任务。

常见失败原因：

| 错误码 | 含义 | 处理 |
| --- | --- | --- |
| `HTTP_STATUS` 404 | 该版本/平台在官方不存在 | 改用其它平台或版本 |
| `BLOCKED_ADDRESS` | 目标解析到内网/保留地址 | 检查数据源配置；内网镜像需显式加入允许列表 |
| `TIMEOUT` | 上游长时间无响应 | 重试；检查代理/网络质量 |
| `DISK_FULL` | 磁盘不足 | 清理存储或扩容 |
| `HASH_MISMATCH` | SHA256 与市场声明不一致 | 重试；持续失败请核对数据源 |
| `SIZE_MISMATCH` | 下载不完整 | 重试以续传 |

## 8. 存储管理

- 查看三类资源的数量与占用、磁盘总量/剩余、临时文件占用。
- 逐项校验 SHA256：重新计算文件哈希并与入库值比对，更新时间戳。
- 删除资源：移除文件与索引，不可恢复。
- 清理临时文件：删除 24 小时前的上传残留与 `.part` 分片。
- **扫描缓存目录**：手动把文件复制进 `data/files`，或直接从目录中删除文件后，点击该按钮即可同步索引，无需重启服务。

扫描会按以下目录结构识别文件：

```text
data/files/
├── vscode/stable/<version>/<platform>/<安装包>
├── remote-server/<version>/<commit>/<platform>/<server 包>
└── extensions/<publisher>/<name>/<version>/<插件>.vsix
```

- 新文件会计算 SHA256 并入库；
- 已存在文件大小变化时会重算哈希并更新；
- 磁盘上已不存在的文件会移除对应索引（扩展图标仅在无其他记录引用时删除）；
- 无法识别路径或元数据的文件会被跳过，并在扫描结果中列出原因。

建议：

- 定期校验重要版本；
- 删除前确认没有任务正在引用；
- 大版本清理后检查磁盘水位。

## 9. 访问分析

「访问分析」记录普通用户的浏览与点击行为：

- 指标：PV、UV、下载量、点击事件、搜索次数，支持今日/7/30/90 天对比。
- 趋势图、Top 页面、Top 下载资源、Top 搜索词。
- 事件明细可按类型、IP、资源、时间段筛选，并导出 CSV。

数据说明：

- 默认记录完整 IPv4/IPv6，保留 90 天（可在设置中改为 30/90/180 天或永久）。
- 访客使用匿名签名 Cookie（`vr_vid`，HttpOnly）区分 UV，不做跨站跟踪。
- 只记录路径、资源、点击目标等运营字段，不记录请求体、密码、Cookie 内容。
- `/admin` 下的操作进入审计日志，不进入访客埋点。
- 点击事件与真实下载分开统计：只有服务端实际开始传输文件才计入下载量。
- 若不需要访问分析，可在设置中整体关闭。

## 10. 日志审计

- **审计日志**：登录成功/失败、退出、改密、缓存任务创建、上传、删除、校验、设置变更等。
- **下载日志**：资源类型/ID、文件名、IP、字节数、HTTP 状态、耗时。
- 支持按动作、关键词（操作者/动作/目标）、分页查询。

建议将容器 stdout 日志接入集中日志系统（Loki/ELK），保留至少 90 天。

## 11. 系统设置

### 数据源

- 插件市场源：官方 / Open VSX；
- 官方市场、Open VSX、VS Code 版本源、下载源地址；
- 修改后可点击「测试」验证连通性与延迟。

> 所有出网请求都会经过 SSRF 防护：仅 http/https，拒绝环回、私网、保留地址。若使用内网镜像，必须在部署时通过 `NETWORK_ALLOWED_PRIVATE_HOSTS` 显式放行（支持精确主机或 `*.example.com`）。

### 访问控制

- 开启「下载需访问码」后，前台浏览与下载需要输入共用访问码；
- 设置新访问码会自动开启开关；留空表示不修改，勾选清除则删除访问码；
- 访问码使用 scrypt 哈希存储，后台不显示明文。

### 性能与限制

- 并发缓存任务数（默认 3，1–16）；
- 单任务最大重试次数（默认 3）；
- 同一 IP 并发下载上限（默认 4）；
- 上传大小上限（默认 200 MB）。

### 修改密码

需要输入当前密码；新密码至少 10 位。修改后其他会话立即失效。

## 12. 公告管理

后台「公告管理」用于向前台用户发布通知、维护窗口、版本提醒等。

- 新建公告：填写标题、内容（纯文本，保留换行）、级别（通知/成功/提醒/重要）、是否置顶、是否发布。
- 生效时间：留空表示立即生效、长期有效；也可以设置定时发布与自动过期。
- 发布后显示在前台页面顶部（最多同时展示 3 条），用户可以关闭；关闭状态保存在浏览器本地。
- 「下线」后立即从前台移除；「删除」不可恢复。
- 所有创建、修改、删除操作都会写入审计日志。

## 13. 按 commit 查找版本

当用户只提供客户端「帮助 → 关于」中的 commit 时：

1. 进入「VS Code 缓存」或「Remote-SSH 缓存」。
2. 在「按 commit 查找版本」输入 7–40 位十六进制 commit。
3. 系统先查本地索引（已缓存资源的 commit），未命中时会在最近 150 个官方稳定版中逐一探测。
4. 找到后会自动把对应版本加入选择，确认平台后即可创建缓存任务。

说明：

- commit 探测需要访问官方源，最近 150 个版本通常需要数秒到十余秒。
- 更早的版本可能不在探测范围内，请直接按版本号搜索。
- 同一 commit 前缀可能匹配多个版本时，会列出多个候选供选择。

## 14. 将本系统接入 VS Code 插件市场

系统内置只读的 VS Code gallery 兼容网关：

- 搜索：`POST /api/gallery/extensionquery`
- 详情/资产：`/api/gallery/asset/...`
- 下载：`/api/gallery/publishers/{publisher}/vsextensions/{name}/{version}/vspackage`

管理员需要：

1. 先在后台缓存需要分发的插件；
2. 在「系统设置 → 数据源」填写「VS Code 接入外部地址」（反向代理场景，留空则使用当前访问地址）；
3. 参照前台「使用说明 → VS Code 接入」修改客户端 `product.json` 的 `extensionsGallery`。

注意：

- 仅返回已缓存插件；未缓存的内容搜索不到。
- 该网关不要求访问码（VS Code 客户端无法携带浏览器 Cookie），请通过内网 ACL 限制来源。
- 修改官方 `product.json` 可能影响应用完整性校验与自动更新，建议在便携版/内部定制版先行测试。

## 15. 备份、恢复与升级

**备份（推荐停机备份）**

```bash
docker compose stop
tar -czf registry-backup-$(date +%F).tar.gz data/
docker compose start
```

`data/` 同时包含 SQLite 数据库与全部缓存文件。数据库使用 WAL 模式，停机复制可避免不一致。

**恢复**

```bash
docker compose down
tar -xzf registry-backup-2026-10-22.tar.gz
docker compose up -d
```

**升级**

```bash
docker compose build --pull
docker compose up -d
```

升级前先备份；数据库迁移在启动时自动执行。

## 13. 运维安全建议

1. 修改默认密码，使用强口令；不要将管理后台暴露到公网。
2. 通过反向代理启用 HTTPS，并设置 `COOKIE_SECURE=auto` 或 `always`。
3. 限制后台访问来源（防火墙/VPN/跳板机）。
4. 定期检查审计日志与失败任务。
5. 按需开启访问码与访问日志保留期。
6. 不要手工修改 `data/` 下的数据库文件；使用后台功能管理资源。
